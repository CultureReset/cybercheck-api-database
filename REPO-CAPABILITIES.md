# CyberCheck API — Full Capability Inventory

What this repo is, everything it exposes, every table the code touches, and what is
wired vs. dead. Generated by reading the source, not the database.

- **907 HTTP endpoints** defined across **34 route files** — 894 of them actually mounted (2 files, 13 routes, are never wired into `server.js`)
- **~230 distinct tables** referenced in code, split across **2 Supabase projects**
- **1 Express app** (`server.js`, 521 lines) deployed serverless on Vercel
- **3 products** served from one codebase

---

## 1. The three products

| Product | What it is | Front door | DB |
|---|---|---|---|
| **CyberCheck** | White-label business dashboard + per-domain public sites for small businesses (bookings, menus, reviews, SMS, payments, site editor) | `/api/auth`, `/api/dashboard`, `/api/public`, `/api/site`, `/api/apps` | Main |
| **Gulf Coast Radar (GCR)** | Local business discovery directory — search, browse, entity profile pages, QR menus, AI chat, ad network | `/api/gcr`, `/api/admin/gcr/*`, `/api/simple`, `/update` | GCR |
| **Trip Swipe** | Tourist itinerary / swipe-to-save app with group planning and an AI concierge | `/api/tourist`, `/api/tourist-auth`, `/api/user` | GCR (auth via GCR Supabase) |

Everything else (Stripe, Square, SMS, QR, rides, charters, rentals, photographers) is shared
machinery both products draw on.

## 2. Boot path — `server.js`

1. CORS from `CORS_ORIGINS`
2. `/api/webhooks` mounted **before** `express.json()` so Stripe raw-body signature verification works
3. `express.json({ limit: '10mb' })` + urlencoded
4. 33 `app.use()` mounts (table below)
5. `/api/site-data` — legacy composite endpoint: bundled `site-data.json` → `site_data_store` blob → live overlay from `businesses` + `site_content` + `media` + `reviews`
6. `/api/upload-image` → hard 503 ("use Supabase Storage on production")
7. `/api/*` 404 handler + global error handler

- **SMS**: Brevo only (`BREVO_API_KEY` + `BREVO_SMS_ENABLED=true`). `utils/sms.js` normalizes

  exist for iMessage OTP.
- **Email**: `utils/email.js` is Brevo HTTP API only, and generates booking confirmation HTML

### Reviews funnel

positive routes to Google link, negative stays internal. Custom per-business review questions.

## 6. Auth

`middleware/auth.js` — `authRequired` accepts three token types in order:
1. Express JWT signed with `JWT_SECRET` (business owners + admin)
2. Legacy main-Supabase JWT (Circle Boats)
3. GCR Supabase JWT (Trip Swipe)

Sets `req.userId` / `req.siteId` / `req.role`, or `req.gcrUserId` / `req.isGCR`.
`adminRequired` = `authRequired` + `role === 'admin'`. Admin login is bcrypt against `users`,
24h JWT.

## 9. What is dead or broken

1. **`module-registry.js` + `modules/`** — the intended plugin architecture. Nothing requires
   it; `mountAll()` is never called. `modules/social-manager/index.js` requires `./routes`,
   which does not exist. `modules/sms-automation/routes.js:180` requires
   `../weather-connector/api`, which does not exist. Its `mountPath` (`/api/modules/...`)
   also collides with the live `routes/modules.js` mount.
2. **`routes/admin-tourists.js` (7 routes)** and **`routes/menu-edit.js` (6 routes)** — never
   mounted in `server.js`.
3. **~156 unauthenticated admin routes** in `admin.js`, including impersonation, business
   CRUD and API-key storage (see §6).
4. **Hardcoded fallback secret** `'gcr-admin-2026'` in `gcr.js` when `GCR_ADMIN_SECRET` is unset.
5. **`POST /api/upload-image`** returns 503 by design on Vercel.
6. **Stale `.bak` files** committed in `routes/`: `dashboard.js.bak`, `public.js.bak`.
7. **No tests, no linter.** `package.json` has only `start`, `dev`, `check`, `check:db`.
8. **Duplicate/legacy table families** — `entity_menu_items` vs `menu_items`,
   `entity_section_items` vs `section_items`, `gcr_menu_items` vs `menu_items`,
   `tourist_saves` vs `tourist_saved_places`, `tourist_memories` vs `tourist_memory`.
   Both halves are referenced in code, from the mid-migration state.
